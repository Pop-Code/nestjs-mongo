    Class EntityManager

    The entity manager is the core of the library: every read and write goes through it.

    One manager exists per connection. Inject it with InjectEntityManager, or use a repository (EntityRepository) that delegates to it for a single model.

    All operations automatically use the mongo session of the current context, if one was set (see EntityManager.startSessionWithTransaction and SessionLoaderMiddleware).

    startSessionWithTransaction

    • startSessionWithTransaction(
          transactionFn: (session: ClientSession) => Promise<any>,
          options?: {
              sessionOptions?: ClientSessionOptions;
              transactionOptions?: TransactionOptions;
              useContext?: boolean;
          },
      ): Promise<ClientSession>

      Start a session and run transactionFn in a transaction (with automatic retries, see ClientSession.withTransaction in the mongodb driver).

      With useContext: true, the session is set on a new session context for the duration of transactionFn, so every operation of the manager (and of the validators) made inside it uses the session without passing it as an option. No middleware is required.

      To avoid Transaction Errors, it is important to keep a sequential approach in the way transactions are commited to the session. ie: do not to use Promise.all (parallel execution) in your transaction function as it could cause inconsistencies in the order in which transactions will be committed to the session.

        } = {}
